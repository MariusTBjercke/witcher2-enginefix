**GOG.** Galaxy's input proxy creates an A and a W object before the game, with different
vtables; the game's own call reuses the W one, and its keyboard gets the filter:

```text
build: 12 feature group(s) not ported to GOG yet (listed above); the rest runs as configured
script patches: book_marker=on continue=on pause_quit=off window_mode=off medallion=on cache=built 78 ms
input: DirectInput8Create (A) from proxydinput_Win32_Release.dll+0x2D6E: CreateDevice hook installed on vtable 5C8E6690
input: DirectInput8Create (W) from proxydinput_Win32_Release.dll+0x324E: CreateDevice hook installed on vtable 5C8E6264
input: DirectInput8Create (W) from witcher2.EXE+0x62380C: CreateDevice hook already there on vtable 5C8E6264
input: keyboard device created by witcher2.EXE+0x62382D (hr 00000000)
input: keyboard state filter installed
input: keyboard device created by dinput8.dll+0x9735 (hr 00000000)
input: keyboard state filter installed
```

`witcher2.EXE+0x62380C` is `00A2380C` at the preferred base, the return address of the call at
`00A23806` in `FUN_00a237a7`. With 0.9.0's single saved original, the first object (A) would have
set it, and the game's W keyboard would have been created through A's `CreateDevice`.

The GOG log of run 2 ends at the last keyboard creation (the main menu after "Exit current
game"), with no `unloaded` line and no shutdown filter line, unlike run 1. The owner quit from
the main menu. No dump, no Application Error event, no WER report; GOG Galaxy logged a normal
close ("The game 'gog_1207658930' is closed", 11:58:50). So the game exited, but the DLL's
detach never wrote. The likely cause, not proven: Windows ends every other thread before
`DLL_PROCESS_DETACH`, and GOG's CRT changes the top-level filter during shutdown (run 1 logged
it 16 ms before `unloaded`), which the worker logs. A worker killed inside `logf_` leaves the log
lock orphaned, and waiting for an orphaned lock during process exit makes Windows end the
process immediately. The detach now only tries the lock when the process is exiting, but the
next GOG run with a save loaded ended the same way (`gog-presets-2026-11-04.md`), so this
explanation is doubtful and the cause is open.
