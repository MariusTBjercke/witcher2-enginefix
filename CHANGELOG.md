# Changelog

Development and GitHub release history. The first Nexus Mods upload is 0.5.0,
with all earlier fixes included in one initial Nexus changelog entry; earlier
versions are not separate Nexus releases.

## 0.10.0

- GOG groundwork: the DLL reads which `witcher2.exe` it runs in (Steam 3.5.0.26 or GOG 3.5.0.26g, from the PE header's time stamp and `.text` size) and runs only what is known on that build. Every fixed game address goes through one lookup, `ga()`, with a per-build table (`k_gog` in `src/enginefix.c`, listed in `docs/addresses.md`) that also adds the load address, because the GOG exe has ASLR. Import slots are found by name in the exe's import directory instead of at fixed addresses; on Steam they are the same slots as before. On GOG this already gives the script patches for book status, Continue and the medallion, the F9/F10 keyboard filter, `cpu32_guard`, crash capture and the interior map files (GOG's map data is byte-identical). The pause menu's Quit waits for `quit_guard`, without which quitting with an area loaded crashes during shutdown. Each feature that is not ported yet logs `not on this build (GOG 3.5.0.26g)` and stays off, where 0.9.0 tried the Steam addresses and relied on its byte checks. Steam behaves as in 0.9.0 (start-tested 2026-11-04; the log has one new `build:` line). `tools/buildprobe` checks the detection, the import slots and the per-build switches against both real exes. See `docs/fixes/gog-build.md`.
- GOG: LOD, the draw distance presets with Ctrl+F10 and the visibility/shadow distance hooks. The settings object (`DAT_025EAEB8`) has the same 50 keys at the same offsets as on Steam. The two renderer sites have the same instructions, but GOG keeps the distance in XMM7, so the range hook's counters use their own bridge there. The Options row for the draw distance stays off on GOG until the window patches are ported. See `docs/fixes/render-distance-experiment.md` and `docs/fixes/graphics-presets.md`.
- GOG: `quit_guard` (FactsAdd at `0050B0A9`, the time kept in another stack slot), `raycast_guard` (the collector's callback is byte-identical) and `skip_intro` (the list builder and the stop take the player in ECX on GOG, so they have their own stubs there). With the quit guard in, the pause menu's Quit is back on GOG. The game global (`VA_GAME`) is ported too. See `docs/fixes/quit-crash.md`, `crash-raycast-stale-body.md` and `skip-intro.md`.
- GOG: the window patches and the Windows keys: Borderless, the live Full screen switch, the Display mode and Draw distance rows in Options (`window_mode`) and Windows key combinations in game. The config writer the Options rows go through is `__thiscall` on GOG (`__stdcall` on Steam), so GOG has its own hook that passes the config manager on in ECX. See `docs/fixes/borderless-window.md` and `windows-keys.md`.
- DirectInput hooks keep one original per vtable. On GOG other modules in the process create DirectInput objects as well, and an A and a W interface have different `CreateDevice` functions, so the single saved original could have called the wrong one for the game's keyboard. The log now names who calls `DirectInput8Create` and who creates the keyboard.
- On exit the DLL only tries the log lock: Windows ends every other thread before the DLL's exit call, and waiting for a lock one of them held would make Windows end the process at once. On GOG the log still usually ends without `unloaded` (not explained yet; the game closes normally); see `docs/fixes/gog-build.md`, "Open".

## 0.9.0

- Medallion on the move (`[scriptpatches] medallion=1`, default): the medallion key works at once. Geralt keeps walking, running or fighting instead of stopping for the use animation, and the cooldown is 1 s instead of 2 s. The pulse, sound and highlights are unchanged, because they belong to the effect and not to the animation. It also works where the animation used to be refused, and Geralt no longer touches the medallion on screen. A medallion started by a quest keeps the animation and 2 s. The patched scripts are rebuilt once (`OV_CACHE_LAYOUT` 6). See `docs/fixes/medallion.md`.
- Fixed: on a CPU with 32 or more logical processors the game never showed a window. Its CPU count (`FUN_00930a6e`) loops on `1 << i` until it passes the system mask or reaches 0, and with the mask `0xFFFFFFFF` neither happens, because x86 masks the shift to 5 bits. `[stability] cpu32_guard=1` (default) reports a process mask of `0x7FFFFFFF` in that case, which skips the count, the same as taking a core away in Task Manager but keeping the core. See `docs/fixes/cpu32-hang.md`. Found in the code; not yet run on such a CPU.
- Fixed: "Script compilation error" naming `W2EF_LootName` and `W2EF_ReadIcon` in `container_class.ws`, seen by a player, most likely with another `guiutils.ws` in play. The book helpers sat at the end of `guiutils.ws`, so a copy of that file from anywhere else took them away while `container_class.ws` kept calling them. They now live in their own script, `game\gui\w2ef_books.ws`, added to the patched archive in CRLF like every game script (`OV_CACHE_LAYOUT` 8). When `guiutils.ws` comes from elsewhere the game now starts and only the read status in the inventory, trade and storage lists is missing; the loot window keeps its markers. See `docs/fixes/shop-book-read-marker.md`.
- Script patches with user content mods: the game compiles a script from the last mounted user content package that has it (`Documents\Witcher 2\UserContent`, listed in `Config\UserContent.ini`) before `base_scripts.dzip`, and of a name held twice in one archive it compiles the last copy. The DLL only patched `base_scripts.dzip`, and there the first copy, so such a mod could hide a patched script and stop the game with "Script compilation error" (the medallion's call from `extendedmovable.ws` into `player.ws` too). The overlay now reads the same list, patches whichever copy the game compiles, in a package's `scripts.dzip` or in `base_scripts.dzip`, and serves a patched copy of that package's `scripts.dzip`; if that copy lacks an anchor, that feature drops as a whole and the game starts without it (`OV_CACHE_LAYOUT` 9). Found in `CompileScriptsFromSources` (`00AA69A0`) and `MountUserContentPackages` (`00ABF177`); see "User content packages" in `docs/fixes/dll-script-patches.md`. `tools\usercontent-test.ps1` sets up a test package.
- Fixed: Quit in the pause menu crashed the game while it shut down. Nobody saw it, because the game was closing anyway, but with `crash_dump=1` each quit left a dump and a `crash:` block in the log. `QuitApplication()` only sets the engine's exit flag, so the area is torn down after the world pointer is gone, and an interaction's last script event calling `FactsAdd` read the default time from it (`00998724`). `[stability] quit_guard=1` (default) makes that read return 0 when the world is gone. See `docs/fixes/quit-crash.md`.
- Fixed: opening the launcher's settings (`bin\Configurator.exe`, which loads `dinput8.dll` too) rotated and rewrote `witcher2_enginefix.log` and `.prev.log`, so the log of a crash was lost. Outside `witcher2.exe` the DLL now only forwards to the system DLL, with no log, hooks or threads.

## 0.8.1

- Fixed: walking out of a Flotsam building (seen at the inn's harbour door), everything in front of Geralt turned see-through, only water showed, until he was outside. The way out loads the town's occluders (invisible blocks the renderer uses to skip what is hidden behind buildings) while the camera is still inside the building's own block, so the renderer culled everything in front of it; the game hid that behind its fade. A kept door now leaves its occluder layers out, and once Geralt is 5 m from the door (at least 0.4 s, at most 30 s) the DLL queues a switch to the partition already current through the game's request function (`FUN_00aa7e18`), whose job loads just the occluders (12-13 ms). Needs the viewport tick (`[window] enabled=1`, the default); without it the occluders load with the door as in 0.8.0.
- The log now says, without `load_trace`, how an area's interiors were found (partition tree or folder names, with the sibling partitions' location types) and lists any layer a house door still had to load that looks like an interior the preload missed, so a player's log shows an area that needs work.

## 0.8.0

- Seamless interiors: walk into houses, shops and inns without a fade (`[loading] interiors=2`, default). Interiors are not separate levels: each is a world partition (a list of layers) inside its own building, and a door swaps partitions. Going into a house the game unloaded the outdoors around it (bushes, rocks, animals, fog, in Flotsam also far buildings, ships and the town's sound) and loaded it all again on the way out, behind a fade. Now:
  - the outdoors stays loaded (visible through the windows); a door only swaps what each place has of its own: ambient sound, occluders, the indoor environment, the area's flat "fake room" boxes and low-poly stand-ins;
  - the area's interiors are loaded together with the area (behind the loading screen or the area-change fade; ~1 s more on loading a save), so open doors show the real rooms and no house door loads anything. The interiors are found from the game's partition tree (an area's indoor sibling partitions) and from their folders (`\buildings\<name>\interior\`, the prologue's `_ints\`);
  - the engine's full object garbage collection is skipped on those doors (25-40 ms each, with nothing to collect);
  - house doors go without a fade; a door whose switch once takes 50 ms or more keeps a 0.05 s fade (`door_fade`);
  - an indoor partition keeps drawing terrain and grass (the game hid them, which made the ground vanish behind Geralt walking in once the fade was gone).
  A door now takes 7-50 ms instead of ~0.65 s (0.7.x) or ~2.2 s (the game). Measured in Binduga, Flotsam (houses, shops, the inn, Sheala's quarter) and the prologue village; process memory ~1.3-1.6 GB in Flotsam with over 1.6 GB of address space free. `interiors=1` keeps the outdoors but loads each interior on its first visit (a short fade then; other houses' open doors show nothing until the next area change); `interiors=0` restores the game's behaviour. Hooks: the partition switch (calls `00AAA1FF`/`00AAB089` -> `FUN_00a91bf9`), its job run (`00A91DAD`), the GC call `00A91AD7`, the door start slot `00EF02E8`, the two fade render commands' execute slots and the indoor draw check `009C0232`. See `docs/fixes/interior-preload.md`.
- Doors that change area, such as the gate into Flotsam (~1 s of real loading), keep a 0.25 s fade (`[loading] area_fade`) so the short house fade does not flash black there.
- Diagnostics: `load_trace` also logs every partition switch (from/to, each layer loaded and unloaded with its path, time), the preloaded interiors with memory before and after, and where Geralt and the door are when a door starts and ends.

## 0.7.0

Includes 0.6.1 (below), which was not released on its own.

- Faster house doors: entering or leaving a house fades to black, swaps in the interior in a fraction of a second and then kept the screen black until the door animation ended (~1.2 s more). A hook on the streaming door's timer (slot `00EF01BC`) now sends the door task its own `fade_out` event as soon as the interior is in and no streaming is pending, and both fades are 0.25 s instead of 0.5 s: a house door is ~0.65 s on screen instead of ~2.2 s, the Flotsam inn 1.2 s instead of 2.5 s (measured in game, the session's first door included). `[loading] fast_doors=0` and `door_fade=0.5` restore the game's timing. Save loading and area transitions were measured too (~3 s for a save, limited by the engine's own single-threaded work) and are unchanged. See `docs/fixes/load-times.md`.
- Crash guard: walking out of the Flotsam inn closed the game once in testing, in a physics ray cast against an object that had just been unloaded (`FUN_0084c750`, from the crash capture's minidump). `[stability] raycast_guard=1` makes the ray miss such an object instead. Not yet seen to trigger in game (two later runs through the same door did not crash). See `docs/fixes/crash-raycast-stale-body.md`.
- Faster save list: to show the Load/Save list (and at game start) the game unpacked every save in full, through a temporary copy on disk, to read four header values (837 MB unpacked for 118 saves). The DLL now unpacks only the 2-3 blocks the list reads, in memory: ~0.9 s per list build instead of ~2.25 s with 120 saves, same list. Loading a save is unchanged. `[saves] fast_list=0` restores the game's way. See `docs/fixes/save-bloat.md`.
- Diagnostics: `[diagnostics] load_trace=1` measures every loading screen and streaming door (length, file reads, block unpacking, sleeps, waits and CPU time per thread); `savelist_trace` now splits each list build into its phases. Both off by default.
- Snipping Tool and Windows keys in game: in play the game reads its DirectInput keyboard in exclusive mode, so Win+Shift+S, Print Screen (when Windows opens the Snipping Tool with it) and every other Windows key combination did nothing while it was in front. The DLL already owns the keyboard device: its `SetCooperativeLevel` now makes it non-exclusive, and the window ignores key messages while DirectInput reads the keyboard, so the game still sees every key once and Alt/F10 do not open the window's system menu. A Windows key tapped on its own is masked so it does not open the Start menu (the Witcher 1 engine fix's method). `[hotkeys] windows_keys=0` restores the block. See `docs/fixes/windows-keys.md`.
- Borderless window: the game has no borderless mode, and its windowed mode gives the window a caption and a border sized so that at the desktop resolution the title bar is off-screen. `[window] borderless=1` makes the window a borderless popup at the configured resolution instead (client area unchanged) while Direct3D stays windowed, so an alt-tab no longer recreates the device. Off by default. Setup: Full screen off and the resolution set to the desktop's. The window patches check the exact 3.5.0.26 instructions before touching anything (the shipped exe is encrypted until its stub jumps to the real entry point, so the DLL waits for the bytes to appear) and skip themselves with a log line on any other build. Options > Graphics switches it in game (below). The process is made DPI-aware before the game creates its window, because the game has no manifest: on a display at anything but 100% scaling Windows would otherwise stretch and clip a 4K window (4K at 150% becomes 5760x3240 physical). `[window] enabled`, `borderless`, `dpi_aware`. See `docs/fixes/borderless-window.md`.
- Options > Graphics now has a "Display mode" row (the game's in-game panel only had Brightness and Gamma; the mode lived in the launcher): full screen, borderless window or windowed, in the game's text language in all twelve languages. It writes the game's own `[Rendering] Fullscreen` and a new `[Rendering] EngineFixBorderless` in `Documents\Witcher 2\Config\User.ini`, and every choice applies at once, without a restart. Borderless and windowed restyle the live window, always at the configured resolution. Full screen on and off runs the engine's own lost-device path (release, then Reset) with the new mode, the code an alt-tab out of full screen already uses, on the game's thread; if the Reset is refused the old mode is kept and the game says so on screen and in the log. `[scriptpatches] window_mode=0` turns the row off. The patched scripts are rebuilt once (`OV_CACHE_LAYOUT`).
- Tools: `check_texts.py` now also checks the new window labels against each language's own font; `tools\windowprobe` runs the config-writer detour against a synthetic `__stdcall` target (built with a `__cdecl` hook it reproduces the first test's crash, so the calling convention stays pinned); the native probes in `tools/distanceprobe` link against the current DLL sources again (they had been stale since 0.6.0 added the script-patch code) and the peer-stop barrier moved to `src/patch_barrier.h`, shared by the distance hooks and the window patches. Offline: 23 `sptest` tests, 15 window-probe checks, 28 distance + 9 hotkey + 21 preset probe checks, `check_texts` for 12 languages.

## 0.6.1

- Crash capture: the game's own crash handler ends the process silently (no message, no Windows error report, no event log entry), so a random crash left nothing to go on. The DLL now puts its own handler in front of it: on a crash it logs the exception, the address as module+offset, the registers, code addresses from the stack and the memory use to `witcher2_enginefix.log`, writes a minidump to `bin\witcher2_enginefix_crash_<date>_<time>.dmp` (newest 5 kept), then hands over to the game's handler as before. `[diagnostics] crash_dump` (1 = log + minidump, 2 = full dump, 0 = off). See `docs/fixes/crash-capture.md`.
- The previous session's log is kept as `witcher2_enginefix.prev.log`; starting the game again after a crash no longer overwrites it. The log can also be read while the game runs (it was opened exclusively before).

## 0.6.0

- The script patches are now built into the DLL and on by default: book marker, Continue in the main menu and Quit in the pause menu work as soon as `dinput8.dll` is in `bin\`, with no `Install.bat` to run. The game's files are never changed: at the first start the DLL builds patched copies of the files it needs (your `base_scripts.dzip`, also Project Mersey's, the trade and storage screens, also HD UI's, and the read-book icons) into `bin\witcher2_enginefix_cache\` (about 0.1 s) and the game reads those instead; later starts reuse them until a game file changes. `[scriptpatches] book_marker`, `continue` and `pause_quit` turn each one off. Uninstalling is deleting the mod's files again. See `docs/fixes/dll-script-patches.md`.
- Upgrading from 0.4/0.5 with the old script patches installed: the first start undoes them once from `Witcher2EngineFix_Optional\ScriptPatches\backup` (only files still exactly as the old patcher left them; a file another mod changed since is left alone and logged) and keeps that backup as `backup.restored-by-dll`. Afterwards the `Witcher2EngineFix_Optional` folder can be deleted.
- No `.bat` or PowerShell script in the release any more. Antivirus heuristics (and the Nexus Mods upload scan) flagged the PowerShell patcher; the zip now holds only the DLL, the ini, the interior maps and the readme.
- Third-party: the DLL includes tinf 1.2.1 by Joergen Ibsen (zlib license) to read the compressed UI movies.

## 0.3.0

- Save list memory leak: every time the Load/Save menu built its list, the game read each save's preview picture from Steam (~0.9 MB) and, when the menu already held that picture, dropped it without freeing it. With 60 saves every menu open cost ~50 MB for the rest of the session; with a few hundred saves it is a few hundred MB per open in a 32-bit game, a likely cause of the crashes players report once saves pile up. The DLL now frees that copy with the game's own destructor (list builder `009A49B9`, AddImage early return `00B2867F`). Confirmed in game: repeat opens 0-1 MB instead of ~50 MB. No save is deleted and the number of saves is not limited. `[saves] fix_list_leak=0` turns it off. See `docs/fixes/save-bloat.md`.
- Diagnostics: `[diagnostics] savelist_trace=1` logs each save-list build (time, Steam reads, previews, process memory before/after) and a memory line every 60 s.

## 0.1.0

First GitHub release, for The Witcher 2: Assassins of Kings - Enhanced Edition 3.5.0.26 (Steam).

- Save previews: new saves (manual saves and QuickSave) get their screenshot in the Load menu again instead of a purple/blue gradient. The save tick (`009B63DE`) queues an in-memory 640x360 capture and saves in the same frame; the capture finishes about a frame later, after `009B7149` already found no image. The DLL keeps that finished BMP and writes it as `<save>_640x360.bmp` through the game's own Steam storage interface. If the game wrote the image itself, nothing is added. `[saves] fix_thumbnails=0` turns it off. The Load menu also reloads previews that were rewritten during the session (QuickSave, reused AutoSave slots); it kept one picture per file name until a restart (`00B28657`), so a new QuickSave showed the previous one. Existing saves keep their missing previews.
- Graphics presets: Ctrl+F10 cycles baseline / high / ultra / extreme, each setting mesh LOD distance, foliage distance, the mesh visibility cutoff and the mesh-shadow distance together, with an on-screen readout. `[presets] default` picks the startup level (extreme).
- Mesh visibility and mesh-shadow distance: two fingerprinted renderer hooks (RVA `0x005BB09F`, `0x005BB465`) scale the game's hard cutoffs; they install only when the exact game code is found.
- LOD values held: `MeshDistanceScale` and `FoliageDistanceScale` stay at the preset values when the options menu rewrites them, and the gameplay LOD downscale flags are kept off.
- Ctrl/Alt+F9/F10 no longer reach the game, so the mod's hotkeys never trigger a quick load; plain F9 is unchanged.
- Diagnostics: `[diagnostics] save_trace=1` logs the save-preview path (Steam writes, screenshot encoding, preview file calls).
