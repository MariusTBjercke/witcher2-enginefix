# Changelog

## 0.5.0

- Optional script patches, the book marker now covers every item list: the "already read" tick and the `Read` / `Nothing new` / `Unread` status also show in Geralt's own inventory, in the trade screen's player list and in the loot window, and the inventory's item tooltip now ends with the status and, for unread books, what reading them still gives (merchants and the storage chest behave as before). The marking moved from the shop script into the shared item fill that every GUI screen uses, so it follows books wherever the game lists them; the loot window has no tooltip at all, so there `(Nothing new)` goes after the name of a book whose knowledge and journal entries are all known already. A book read in the inventory updates there at once (the list is refilled like after trashing an item, keeping its scroll position) instead of on the next open. The tick now also shows on Geralt's side of the trade and storage screens (they cleared it there; the same kind of same-length no-op as on the merchant side), so a book's status is visible in every window where it can be handled. The tick now means read only (at a merchant and in the storage chest also "you carry one", as before); a book with nothing new keeps its plain icon and says so in its status and tooltip, since its text is still unread. In the loot window and the small preview next to a container, a read book shows its own icon with the inventory's tick drawn on it: Install builds these icons from the game's own files (152 books in a full install) into `CookedPC\globals\gui\icons\items\w2ef_read\`, and Uninstall removes them. If another UI mod replaced the trade or storage screen, the patcher leaves it alone and only the tick there is missing. `Witcher2EngineFix_Optional\ScriptPatches\Install.bat` re-applies it (Uninstall still restores the modded originals byte for byte). See `docs/fixes/shop-book-read-marker.md`. The DLL is unchanged apart from its version.

## 0.4.0

- Skip intro: `[startup] skip_intro=1` (off by default) starts at the main menu without the logo videos and the intro movie. The startup movies come from `globals\video_start.csv`; the game only finishes that sequence after at least one movie, so an empty table leaves a black screen until a key is pressed (which is why intro-removal mods keep one logo). The DLL instead presses "skip" for each startup movie once it has played 300 ms, through the game's own Esc path (`009A1F2E`), from a wrapped tick (`00ECAF78`) armed only by the startup list build (`009B588F`). A short black moment remains. See `docs/fixes/skip-intro.md`.
- Optional script patches, off until `Witcher2EngineFix_Optional\ScriptPatches\Install.bat` is run (it asks for each, and patches the files the game actually uses: `base_scripts.dzip` also when Project Mersey replaced it, the trade/storage screens also when an HD UI mod replaced them; originals in its `backup\`, `Uninstall.bat` restores them):
  - Shop book marker: the A Better UI "already read" overlay on merchant and storage books only meant "you carry a copy". It now also shows for books read before (the game's `<item>_Examined` fact) and for books whose bestiary knowledge and journal entries are all known already. The list shows `Read` / `Nothing new` / `Unread` after the item type and the tooltip lists what is still new. Texts in 12 languages, every character checked against the game's own texts. See `docs/fixes/shop-book-read-marker.md`.
  - Continue: a Continue button at the top of the main menu loads the newest save (the game's own `menuContinue` label).
  - Quit in the pause menu: the game's Quit button with a confirmation, next to "Exit to main menu". See `docs/fixes/menu-buttons.md`.
- Tools: `tools\script-patches\check_texts.py` decodes the game's `.w2strings` and checks the book marker's translations against them. `docs/research.md` section 9 documents the DZIP and `.w2strings` formats and the script compiler's keywords.

## 0.3.0

- Save list memory leak: every time the Load/Save menu built its list, the game read each save's preview picture from Steam (~0.9 MB) and, when the menu already held that picture, dropped it without freeing it. With 60 saves every menu open cost ~50 MB for the rest of the session; with a few hundred saves it is a few hundred MB per open in a 32-bit game, a likely cause of the crashes players report once saves pile up. The DLL now frees that copy with the game's own destructor (list builder `009A49B9`, AddImage early return `00B2867F`). Confirmed in game: repeat opens 0-1 MB instead of ~50 MB. No save is deleted and the number of saves is not limited. `[saves] fix_list_leak=0` turns it off. See `docs/fixes/save-bloat.md`.
- Diagnostics: `[diagnostics] savelist_trace=1` logs each save-list build (time, Steam reads, previews, process memory before/after) and a memory line every 60 s.

## 0.2.0

- Interior maps: the map screen (M) no longer shows a black local map with one huge pin in 25 interior map entries: temples, inns, Loredo's house, towers and other houses. The game's `globals\map_scales.csv` has no big map for these areas, so the panel loaded an empty image name. The zip now ships a filled-in `map_scales.csv` and 2048x2048 upscales of each area's own minimap as loose files under `CookedPC\globals\`. Upscaled because the map panel's zoom runs backwards on images smaller than the panel. Data only; the DLL is unchanged apart from its version. Generated from the game's own `pack0.dzip` by `tools\build-interior-maps.py`. See `docs/fixes/interior-maps.md`.

## 0.1.0

First public release, for The Witcher 2: Assassins of Kings - Enhanced Edition 3.5.0.26 (Steam).

- Save previews: new saves (manual saves and QuickSave) get their screenshot in the Load menu again instead of a purple/blue gradient. The save tick (`009B63DE`) queues an in-memory 640x360 capture and saves in the same frame; the capture finishes about a frame later, after `009B7149` already found no image. The DLL keeps that finished BMP and writes it as `<save>_640x360.bmp` through the game's own Steam storage interface. If the game wrote the image itself, nothing is added. `[saves] fix_thumbnails=0` turns it off. The Load menu also reloads previews that were rewritten during the session (QuickSave, reused AutoSave slots); it kept one picture per file name until a restart (`00B28657`), so a new QuickSave showed the previous one. Existing saves keep their missing previews.
- Graphics presets: Ctrl+F10 cycles baseline / high / ultra / extreme, each setting mesh LOD distance, foliage distance, the mesh visibility cutoff and the mesh-shadow distance together, with an on-screen readout. `[presets] default` picks the startup level (extreme).
- Mesh visibility and mesh-shadow distance: two fingerprinted renderer hooks (RVA `0x005BB09F`, `0x005BB465`) scale the game's hard cutoffs; they install only when the exact game code is found.
- LOD values held: `MeshDistanceScale` and `FoliageDistanceScale` stay at the preset values when the options menu rewrites them, and the gameplay LOD downscale flags are kept off.
- Ctrl/Alt+F9/F10 no longer reach the game, so the mod's hotkeys never trigger a quick load; plain F9 is unchanged.
- Diagnostics: `[diagnostics] save_trace=1` logs the save-preview path (Steam writes, screenshot encoding, preview file calls).
